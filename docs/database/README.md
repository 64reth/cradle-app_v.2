# Database Foundation

Phase 2 establishes only foundation tables:

- `households`
- `members`
- `sessions`
- `invitation_codes`

Rooms, tasks, routines, systems, maintenance, plans, reviews, and companion persistence are intentionally out of scope for this phase.

## Naming Conventions

- Table names use plural snake_case nouns.
- Primary IDs are text UUID-style identifiers generated by future application code.
- Tenant-owned tables include `household_id`.
- Tenant-owned primary keys use `(household_id, id)` where records belong to one household.
- Timestamps use UTC ISO-8601 text in `created_at` and `updated_at`.
- Foreign keys are explicit and migration tests enable `PRAGMA foreign_keys = ON`.

## Migration Workflow

Apply local migrations:

```bash
npm run db:migrate
```

List local migrations where Wrangler supports it:

```bash
npm run db:migrations:list
```

Reset local D1 state:

```bash
npm run db:reset:local
npm run db:migrate
```

The reset script only removes `.wrangler/state/v3/d1` in the current project.

## Recovery

If a local migration fails:

1. Read the Wrangler error and fix the migration or configuration root cause.
2. If the local database is half-applied and disposable, run `npm run db:reset:local`.
3. Reapply with `npm run db:migrate`.
4. Run `npm test` to confirm the clean SQLite migration tests still pass.
